# الدفاتر البرمجية

اثنا عشر دفترًا، دفتر لكل فصل له دفتر. وهي غير مطبوعة في الكتاب: الكتاب يشير إلى هنا، حتى يمكن تصحيح الدفتر عند تغيّر إحدى المكتبات وتوسيعه عند ظهور ما يستحق العرض.

!!! success "كل دفتر يعمل من أوّله إلى آخره دون أي تنزيل ودون حسابات"
    حيثما تعذّر توفّر مدوّنة حقيقية أو نموذج مُدرَّب مسبقًا، يحلّ محلّه **بديل** مُعلَّم بوضوح، ويطبع الدفتر المسار الذي سلكه. والخلايا التي تحتاج تنزيلًا مُعلَّمة بـ `OPTIONAL` ويمكن تخطّيها بأمان.

## تشغيلها

=== "محليًّا"

    ```bash
    pip install -r requirements.txt
    jupyter lab
    ```

    [ملف المتطلّبات المثبّت](requirements.txt) صغير: الكتلة الأولى هي كل ما تحتاجه الدفاتر الاثنا عشر للعمل من أوّلها إلى آخرها. أما الكتلة الثانية (torch وtransformers وdatasets…) فهي للخلايا `OPTIONAL` فقط ومُعلَّقة — أزِل التعليق عمّا تحتاجه.

=== "Google Colab"

    افتح الدفتر وشغّله. الكتلة الأولى من `requirements.txt` مثبّتة هناك مسبقًا. ولأي خلية `OPTIONAL`، شغّل سطر pip المطبوع أعلى الدفتر الذي يحتاجه.

## قاعدتان جديرتان بالالتزام

!!! abstract "خلية إثبات المصدر"
    ينتهي كل دفتر بواحدة. تطلب المدوّنة وإصدارها، والرخصة، والنموذج ومراجعته، والتطبيع المطبَّق قبل القياس، والتاريخ. املأها قبل اقتباس أي رقم أنتجه الدفتر — فهي الفرق بين نتيجة ولقطة شاشة.

!!! abstract "لكل لهجة، دائمًا"
    تحسب عدّة دفاتر رقمًا مجمّعًا ثم تفصّله. **التفصيل هو المقصد.** فالرقم العربي المجمّع متوسّط على أشياء ليست الشيء نفسه، وقد يبدو جيّدًا بينما يفشل نوع بأكمله.

## إعادة البناء

الدفاتر *مولَّدة*، حتى تشترك الاثنا عشر في بنية واحدة ومجموعة اصطلاحات واحدة. يعيش المولِّد (`nbbuild.py` ودفتر `build_chNN.py` لكل دفتر) في مجلد `notebooks-src/build/` بالمستودع. عدِّل المولِّد لا الدفتر إن أردت لتغييرٍ أن يبقى بعد إعادة التوليد التالية.
